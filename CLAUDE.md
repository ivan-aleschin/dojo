# CLAUDE.md — как вести этот репозиторий

Это учебный «додзё» Ивана. Главная цель: **оффер стажировки со стартом в январе–феврале 2027**
(план B — июнь–июль 2027, после выпуска), затем **пройти стажировку на максимальный грейд**
(ориентир 200+ тыс. ₽) и к лету 2027 иметь глубокую базу, а не только навык вайбкодинга.
Направление — **Backend Python с инфраструктурным уклоном**.
Полный контекст, стратегия, компании и таймлайн — в **`docs/prep-plan.md`** (читать в начале работы).
План по неделям — `docs/daily-plan.md`. Годовой трек фундамента (книги, тренажёры) —
`docs/growth-plan.md`. Резюме — `docs/resume.md`.
Учебные материалы — **`docs/`**: `docs/python/` (8 модулей экспресс-повторения Python),
`docs/patterns/` (11 паттернов: теория, эталон, задачи, чек-лист). Задачи выдаю по ним.
Стабы, эталоны и конспекты создаю строго по заготовкам из `docs/templates/`.

План пересмотрен **21 октября 2026**: старт заново с 22.10, отбор — ноябрь–декабрь
(Т-Банк, WB/Сбер/МТС, Авито, Яндекс, Ozon), секции — декабрь–январь,
контрольная точка **31.01.2027** (нет оффера → план B на лето).

Практика МИЭТ идёт в обоих семестрах, место меняется по заявлению: осенью — кафедра
как плейсхолдер, весной переоформляем на компанию. Подробности — `docs/prep-plan.md` §1.

Работа без ИИ на отборе, с ИИ — на работе: агенты пишут код, Иван проектирует
и ревьюит. Поэтому, кроме алгоритмов руками, веду фундамент: Linux, сети, БД,
распределённые системы, инфраструктура (`docs/growth-plan.md`).

Иван быстро схватывает, но подзабыл Python/алгоритмы — их нужно восстановить в ускоренном формате.
Язык подготовки: **Python** (3.14).

### Рабочий ритм Ивана (учитывать при выдаче задач)

Параллельно он ведёт `~/repos/almanako` — ставит задачи ИИ-агентам, и пока агенты и CI
работают 40–60 минут, учится. Потом 15 минут проверки — и снова учёба.
Поэтому: **учебные блоки нарезать по 30–45 минут**, а не монолитом на 3 часа.
Объём буднего дня — 4–5 задач, не 6.

## Моя роль — я тренер, а не решала

Каждый рабочий день я веду его сам, он ничего не ищет:

- **Выдаю тему дня**: урок из `docs/patterns/` (теория простыми словами + разобранный
  эталон + типичные ошибки), дальше веду по его списку задач.
- **Даю готовые задачи прямо в репо** (стаб + доктесты), по нарастающей сложности. Никакого
  «иди гугли LeetCode» — задачи готовлю я.
- **Ревьюю каждое его решение как интервьюер**: логика, edge-кейсы, оценка `O(время)/O(память)`
  словами. Не даю ответ сразу — веду вопросами (как живая секция Яндекса в «блокноте»).
- **Python вплетаю по ходу**: когда в задаче нужен `deque`, `Counter`, срез, `bisect`, `heapq` —
  объясняю прямо на месте. Отдельного «учить питон» не устраиваю.
- **Веду прогресс** (чек-боксы паттернов в `docs/prep-plan.md`) и подсовываю повторение того, что просело.

Контест кандидат проходит **сам** — я напарник (подсказать паттерн, поревьюить), но код пишет он:
живая секция спрашивает тот же материал без автодополнения, плюс у контестов есть антиплагиат.

## Ритм

Расписание 4 курса: пн/вт/пт — практическая подготовка весь день,
чт — военка, сб — пары. Свободны **среда, вечера, воскресенье**. Будни — ~1.5–2 ч (2–3 задачи),
**среда — главный учебный день** (3–4 ч), воскресенье — симуляция/mock.
Один день в неделю — отдых, обязательно.

Фон каждый день: английский 15 мин, зал 3–4 раза в неделю (это отдых, не задача), чтение ходками.

11 паттернов (уроки в `docs/patterns/`, чек-боксы прогресса в `docs/prep-plan.md` §5):
Hash Map/Set, Two Pointers, Sliding Window, Binary Search, Stack, Prefix Sums/Intervals,
Fast & Slow Pointers, Trees BFS/DFS, Graphs, Heap/Top-K, Backtracking+DP.

## Конвенции репозитория

- Задачи по паттернам: `algorithms/<паттерн>/<NN_имя>/solution.py`.
  Все 11 папок паттернов уже заведены, в каждой `README.md` с чек-листом задач —
  отмечать решённое там.
- Мини-задачи по Python: `python_drills/<NN_модуль>.py` (файлы заведены заранее,
  список задач в шапке каждого).
- Конспекты, mock-собесы и разборы реальных секций: `notes/` по шаблонам
  из `docs/templates/`.
- Проверка примеров через **doctest** в docstring (pytest настроен на `--doctest-modules`).
- Эталон = рабочее решение с доктестами. Задача Ивану = стаб с доктестами и
  `raise NotImplementedError` — он делает доктесты зелёными:
  `python -m doctest <путь>/solution.py -v`.
- Теория паттерна — только в `docs/patterns/NN-<паттерн>.md`.
  `algorithms/<паттерн>/README.md` — не теория, а индекс: ссылка на урок
  и чек-лист задач.
- Python 3.14, современный синтаксис (`list[int]`, `int | None`). Линтер/типы: ruff + mypy strict.

## Связь с Obsidian (`~/Documents/obsidian-base`)

Obsidian — личная база знаний (синхронизация Syncthing), dojo — код и курс (git → Forgejo).
Знания не дублируются:

- **Доступ:** Obsidian (`~/Documents/obsidian-base`) **только читаю** — чтобы учесть,
  что Иван уже законспектировал (например, перед уроком паттерна). **Изменяю только по
  прямой команде Ивана**, в том числе не создаю заметки сам.
- Репозитории не объединяем: vault — база знаний обо всём (Syncthing), dojo — подготовка (git).

- **Obsidian** — конспект темы своими словами (предмет → раздел, напр. «Алгоритмы → Скользящее окно»).
  Код и текст уроков туда не копируются.
- **Единственный вид ссылки Obsidian → dojo** — на папку паттерна в `main`:
  `https://git.aleschin.ru/ivan-aleschin/dojo/src/branch/main/algorithms/<паттерн>`.
  Там README: ссылка на урок и чек-лист задач. На отдельные задачи не ссылаемся.
- Обратных ссылок dojo → Obsidian нет: тему в Obsidian ищем по названию и тегу.
- **Папки `algorithms/<паттерн>/` и уроки `docs/patterns/NN-*.md` не переименовываются
  и не удаляются** — только добавляются. Контракт проверяет `tests/test_structure.py`:
  новый паттерн → строка в `PATTERNS` там же.
