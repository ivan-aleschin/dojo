# Паттерн 02 — Two Pointers (два указателя)

> **Приоритет: отбор.** Даёт `O(1)` памяти там, где хеш требует `O(n)`.
> Любимый вопрос-продолжение: «а можно без дополнительной памяти?»

## Идея простыми словами

Держим **два индекса** вместо вложенного цикла. Каждый шаг гарантированно
отбрасывает часть вариантов, поэтому суммарно указатели проходят массив
один раз → `O(n)` время, `O(1)` память.

Работает только там, где есть **монотонность**: свойство «если сдвину сюда, станет
только больше/меньше». Обычно её даёт сортировка.

## Три схемы

**1. Навстречу** — `left = 0`, `right = n - 1`, сходятся к центру.
Two Sum в отсортированном, палиндром, Container With Most Water.

**2. Догоняющие (медленный/быстрый в одном направлении)** — `slow` пишет,
`fast` читает. Удаление дубликатов на месте, перенос нулей в конец.

**3. Два массива** — по указателю на каждый. Слияние отсортированных,
пересечение, `is_subsequence`.

## Триггеры

- массив/строка **отсортированы** + ищем пару/тройку по условию на сумму;
- сравнение **с двух концов**: палиндром, разворот;
- модификация **на месте** («in-place», «без дополнительной памяти»);
- слияние или сравнение **двух отсортированных** последовательностей;
- в условии явно: «память `O(1)`».

## Скелеты кода

**Навстречу**

```python
left, right = 0, len(a) - 1
while left < right:
    if condition_met(a[left], a[right]):
        return ...
    if too_small:
        left += 1
    else:
        right -= 1
```

**Догоняющие (запись на месте)**

```python
slow = 0
for fast in range(len(a)):
    if keep(a[fast]):
        a[slow] = a[fast]
        slow += 1
return slow          # длина «полезной» части
```

**Два массива**

```python
i = j = 0
while i < len(a) and j < len(b):
    if a[i] < b[j]:
        i += 1
    elif a[i] > b[j]:
        j += 1
    else:
        # совпадение
        i += 1
        j += 1
```

## Разобранный эталон: Container With Most Water

> Дан массив высот `height`. Выбрать две линии, чтобы вместе с осью X они
> образовали сосуд максимального объёма. Вернуть максимум.

**Уточнения:** высоты неотрицательные? линии наклонять нельзя? `n ≥ 2`?

**Наивно:** все пары, `O(n²)`. При `n = 10⁵` — не проходит.

**Идея.** Объём = `min(h[l], h[r]) * (r - l)`. Ставим указатели по краям —
это максимально возможная **ширина**. Двигать можно только внутрь, значит ширина
только уменьшается. Чтобы был шанс на бóльший объём, должна вырасти высота —
а она ограничена **меньшей** из двух линий. Значит сдвигать надо ту, что меньше:
сдвиг большей гарантированно ухудшает результат.

Это и есть монотонность, которая делает паттерн корректным. Проговорить именно
это рассуждение — то, что оценивают на секции.

```python
def max_area(height: list[int]) -> int:
    """Максимальный объём воды между двумя линиями.

    Время O(n), память O(1).

    >>> max_area([1, 8, 6, 2, 5, 4, 8, 3, 7])
    49
    >>> max_area([1, 1])
    1
    >>> max_area([4, 3, 2, 1, 4])
    16
    """
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        area = min(height[left], height[right]) * (right - left)
        best = max(best, area)
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    return best
```

**Сложность:** каждый шаг сдвигает ровно один указатель, суммарно `n` шагов →
`O(n)` время, `O(1)` память.

## Пропуск дубликатов — обязательный приём (3Sum)

Когда задача требует **уникальные** тройки, после найденного ответа надо
проматывать одинаковые значения:

```python
def three_sum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                      # пропускаем дубль первого числа
        left, right = i + 1, len(nums) - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1             # пропускаем дубли внутри
    return res
```

Время `O(n²)` (внешний цикл × два указателя), память `O(1)` без учёта ответа.
3Sum — классика технической секции и регулярно всплывает на отборах.

## Типичные ошибки

1. **`while left <= right` вместо `<`** — элемент паруется сам с собой.
2. **Забыли отсортировать.** Паттерн без монотонности неверен.
3. **Не пропущены дубликаты** в 3Sum → повторы в ответе.
4. **Сдвигают не тот указатель** (в Container сдвигают больший) → неверный ответ
   на тестах вида `[1, 8, 6, 2, 5, 4, 8, 3, 7]`.
5. **Забывают вернуть длину** в задачах «на месте» — там ответ обычно не массив,
   а количество полезных элементов.
6. **Модифицируют вход, не спросив.** На собесе стоит уточнить: «можно ли портить входной массив?»
