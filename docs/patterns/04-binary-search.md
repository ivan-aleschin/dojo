# Паттерн 04 — Binary Search (бинарный поиск)

> **Приоритет: отбор.** На отборочных почти всегда есть одна задача,
> где `n ≤ 10⁹` — это прямая подсказка «бинпоиск по ответу».

## Идея простыми словами

Если пространство ответов **отсортировано** (или обладает свойством
«до какого-то момента нет, после — да»), можно каждый раз отбрасывать половину.
`log₂(10⁹) ≈ 30` — тридцать шагов вместо миллиарда.

Бинпоиск бывает двух совершенно разных видов, и второй важнее первого:

**1. Поиск в массиве** — «найди индекс числа».
**2. Бинпоиск по ответу** — «найди минимальное X, при котором задача решается».
Массива нет вообще; есть монотонная функция-проверка `can(x)`.

## Триггеры

- слово **«отсортированный»** в условии;
- `n` до 10⁹ / 10¹⁸ — перебирать нельзя, значит по ответу;
- «минимальная скорость / минимальное время / максимальный размер, чтобы …»;
- ответ обладает свойством: если `X` подходит, то и любой больший (или меньший) подходит;
- «найти первый / последний элемент, удовлетворяющий условию».

## Скелет №1: классический поиск

Пиши **всегда в одной форме**, чтобы не путаться. Рекомендуемая — полуинтервал:

```python
def binary_search(a: list[int], target: int) -> int:
    lo, hi = 0, len(a)          # hi ИСКЛЮЧАЕТСЯ: ищем в [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return -1
```

Инвариант: ответ всегда лежит в `[lo, hi)`. Цикл идёт, пока отрезок непуст.

## Скелет №2: первая позиция, где условие истинно (главный)

Это форма, которая закрывает 90% задач: `lower_bound`, `upper_bound`,
поиск границ, бинпоиск по ответу.

```python
def first_true(lo: int, hi: int, ok) -> int:
    """Минимальный x в [lo, hi], для которого ok(x) == True.

    Требование: ok монотонна — False, False, ..., False, True, True, ..., True.
    Возвращает hi, если такого x нет (при hi как «заведомо истинной» границе).
    """
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid            # mid может быть ответом — НЕ отбрасываем
        else:
            lo = mid + 1        # mid точно не ответ
    return lo
```

Запомни правило: **`hi = mid`, если `mid` может быть ответом; `lo = mid + 1`, если точно нет.**
`+1` ставится только у той границы, что двигается вверх — иначе вечный цикл.

## Разобранный эталон: Koko Eating Bananas (бинпоиск по ответу)

> Кучи бананов `piles`, у Коко `h` часов. За час она съедает `k` бананов из одной кучи
> (если в куче меньше — доедает и ждёт). Найти минимальную скорость `k`,
> чтобы успеть за `h` часов.

**Шаг 1. Где здесь монотонность?** Если скорость `k` успевает, то `k + 1`
тем более успевает. Значит функция «успевает(k)» имеет вид `False...False True...True`.
Ответ — первая `True`.

Это и есть весь трюк: не ищем в массиве, а ищем **в диапазоне ответов**.

**Шаг 2. Границы.** Минимальная осмысленная скорость — 1. Максимальная — `max(piles)`
(быстрее незачем: за час всё равно одна куча). Значит ищем в `[1, max(piles)]`.

**Шаг 3. Функция проверки.** Часы при скорости `k`:
`sum(ceil(pile / k))`. Целочисленный потолок в Python: `(pile + k - 1) // k`
или `-(-pile // k)`.

```python
def min_eating_speed(piles: list[int], h: int) -> int:
    """Минимальная скорость, при которой Коко успевает за h часов.

    Бинпоиск по ответу. Время O(n log(max(piles))), память O(1).

    >>> min_eating_speed([3, 6, 7, 11], 8)
    4
    >>> min_eating_speed([30, 11, 23, 4, 20], 5)
    30
    >>> min_eating_speed([30, 11, 23, 4, 20], 6)
    23
    """
    def hours_needed(k: int) -> int:
        return sum((pile + k - 1) // k for pile in piles)

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if hours_needed(mid) <= h:
            hi = mid          # успеваем — пробуем медленнее
        else:
            lo = mid + 1      # не успеваем — надо быстрее
    return lo
```

**Сложность вслух:** «`log(max(piles))` итераций, в каждой проход по `n` кучам →
`O(n log max)`. Памяти `O(1)`».

Тот же шаблон закрывает: «минимальная вместимость корабля», «разделить массив
на k частей с минимальной максимальной суммой», «минимальное время на изготовление».
Отличается только `ok(x)`.

## Скользкие места классического поиска

**Найти первое и последнее вхождение** (Find First and Last Position):

```python
import bisect
first = bisect.bisect_left(a, target)     # первое >= target
last = bisect.bisect_right(a, target) - 1 # последнее <= target
if first > last:
    return [-1, -1]
```

Уметь надо и руками: `bisect_left` — это `first_true(lambda i: a[i] >= target)`.

**Поиск в повёрнутом массиве** (Search in Rotated Sorted Array): массив
отсортирован, но «прокручен». На каждом шаге **одна из половин обязательно
отсортирована** — определяем какая, и смотрим, попадает ли `target` в её диапазон:

```python
lo, hi = 0, len(a) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if a[mid] == target:
        return mid
    if a[lo] <= a[mid]:                    # левая половина отсортирована
        if a[lo] <= target < a[mid]:
            hi = mid - 1
        else:
            lo = mid + 1
    else:                                   # правая отсортирована
        if a[mid] < target <= a[hi]:
            lo = mid + 1
        else:
            hi = mid - 1
return -1
```

## Типичные ошибки

1. **Вечный цикл** — `lo = mid` без `+1`. Всегда проверяй на входе из 2 элементов.
2. **Смешение стилей** `[lo, hi]` и `[lo, hi)` в одном решении.
3. **Неверные границы в бинпоиске по ответу** — `hi` должно быть заведомо
   достижимым ответом, иначе ответ вне диапазона.
4. **Немонотонная проверка** — паттерн просто неприменим, нужно доказать монотонность.
5. **Ищут в неотсортированном** и не замечают этого.
6. **`(lo + hi) // 2` боятся из-за переполнения** — в Python его нет,
   но на собесе можно упомянуть `lo + (hi - lo) // 2` как привычку из C++.
