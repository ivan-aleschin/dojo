# Часть 1. Префиксные суммы

## Идея простыми словами

Считаем один раз массив накопленных сумм — после этого сумма **любого** отрезка
достаётся за `O(1)` вычитанием.

```
nums    = [2, 4, 1, 5]
prefix  = [0, 2, 6, 7, 12]      # prefix[i] = сумма первых i элементов
```

Сумма отрезка `nums[l..r]` (включительно) = `prefix[r + 1] - prefix[l]`.

Лишний нуль в начале — не украшение, а способ убрать `if l == 0` из кода.
Пиши всегда с ним.

```python
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
# или: prefix = [0] + list(itertools.accumulate(nums))
```

Стоимость: `O(n)` подготовка, потом `O(1)` на запрос.
Окупается, если запросов много или отрезок ищется внутри цикла.

## Триггеры

- «сумма подмассива», особенно **много запросов** сумм;
- «подмассив с суммой ровно K» (и есть отрицательные — [окно](03_sliding_window.md) не годится);
- «сбалансированный», «pivot index», «равное количество нулей и единиц»;
- «сколько подмассивов удовлетворяют условию на сумму».

## Приём, который надо знать наизусть: prefix + hash

> **Subarray Sum Equals K:** сколько подмассивов имеют сумму ровно `k`?
> Числа могут быть отрицательными.

Сумма `nums[l..r] = prefix[r+1] - prefix[l]`. Нужно `prefix[r+1] - prefix[l] == k`,
то есть `prefix[l] == prefix[r+1] - k`. Значит, идя по массиву, для текущей
префиксной суммы надо знать, **сколько раз раньше встречалась** сумма `cur - k`.
Это словарь частот.

```python
from collections import defaultdict

def subarray_sum(nums: list[int], k: int) -> int:
    """Количество подмассивов с суммой ровно k.

    Время O(n), память O(n).

    >>> subarray_sum([1, 1, 1], 2)
    2
    >>> subarray_sum([1, 2, 3], 3)
    2
    >>> subarray_sum([1, -1, 0], 0)
    3
    """
    seen = defaultdict(int)
    seen[0] = 1              # пустой префикс — иначе потеряем подмассивы с начала
    cur = 0
    count = 0
    for x in nums:
        cur += x
        count += seen[cur - k]
        seen[cur] += 1
    return count
```

`seen[0] = 1` — самая частая потерянная строчка в этой задаче.

Тот же приём с заменой «сумма» на «остаток от деления» решает
«подмассив, сумма которого делится на K», а с заменой 0 на −1 —
«самый длинный подмассив с равным числом нулей и единиц».

## Двумерные префиксы (для полноты)

`pref[i][j]` — сумма прямоугольника от `(0,0)` до `(i-1,j-1)`.
Сумма прямоугольника — по формуле включений-исключений:

```python
total = pref[r2+1][c2+1] - pref[r1][c2+1] - pref[r2+1][c1] + pref[r1][c1]
```

Встречается в задаче **Range Sum Query 2D**. Знать формулу, вывести на бумаге.

## Разностный массив (difference array)

Обратная идея: много операций «прибавить `v` на отрезке `[l, r]`», а ответ нужен
в конце. Вместо `O(n)` на операцию — `O(1)`:

```python
diff = [0] * (n + 1)
for l, r, v in updates:
    diff[l] += v
    diff[r + 1] -= v
# восстановление
cur = 0
result = []
for i in range(n):
    cur += diff[i]
    result.append(cur)
```

Этот приём — типовое решение задач «Corporate Flight Bookings», «Car Pooling».

# Часть 2. Интервалы

## Идея простыми словами

Почти все задачи на отрезки решаются одинаково: **отсортировать по левой границе**
и пройти один раз, поддерживая «текущий» отрезок.

Два отрезка `[a1, b1]` и `[a2, b2]` пересекаются ⟺ `a1 <= b2 and a2 <= b1`.
После сортировки условие упрощается до `a2 <= b1`.

## Скелет: слияние отрезков

```python
def merge(intervals: list[list[int]]) -> list[list[int]]:
    """Слить пересекающиеся отрезки.

    Время O(n log n) (сортировка), память O(n) на ответ.

    >>> merge([[1, 3], [2, 6], [8, 10], [15, 18]])
    [[1, 6], [8, 10], [15, 18]]
    >>> merge([[1, 4], [4, 5]])
    [[1, 5]]
    """
    intervals.sort(key=lambda x: x[0])
    out: list[list[int]] = []
    for start, end in intervals:
        if out and start <= out[-1][1]:        # пересекается с последним
            out[-1][1] = max(out[-1][1], end)  # max обязателен: [1,10],[2,3]
        else:
            out.append([start, end])
    return out
```

`max` в строке слияния — то место, где теряют баллы: без него отрезок `[1,10]`
после слияния с `[2,3]` схлопнется в `[1,3]`.

## Скелет: «сколько одновременно» (sweep line)

«Минимальное число переговорок», «максимум одновременных встреч» — превращаем
отрезки в события `+1` на входе и `-1` на выходе, сортируем и идём:

```python
events = []
for start, end in intervals:
    events.append((start, 1))
    events.append((end, -1))
events.sort()                 # при равном времени -1 раньше +1: (t, -1) < (t, 1)
cur = best = 0
for _, delta in events:
    cur += delta
    best = max(best, cur)
```

Порядок при совпадении времени — это уточняющий вопрос к интервьюеру:
считается ли, что встреча, кончающаяся в 10:00, конфликтует с начинающейся в 10:00?
Кортеж `(t, -1)` сортируется раньше `(t, 1)`, то есть по умолчанию — не конфликтует.

Альтернатива через кучу — в [паттерне 10](10_heap_topk.md).

## Типичные ошибки

1. **Забыт `max` при слиянии** правых границ.
2. **Не отсортировали** перед проходом.
3. **Забыт `seen[0] = 1`** в prefix+hash.
4. **Границы включительно/исключительно** перепутаны — всегда уточнять у интервьюера.
5. **Пытаются применить скользящее окно** к массиву с отрицательными числами.
   Правильный ответ — префиксы плюс хеш.
6. **Пересчитывают сумму отрезка в цикле** → `O(n²)` вместо `O(n)`.
