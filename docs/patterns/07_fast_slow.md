# Паттерн 07 — Fast & Slow Pointers + связные списки

> **Приоритет: технические секции.** На отборах реже, на живых собесах —
> постоянно: списки хорошо показывают аккуратность работы со ссылками.

## Идея простыми словами

Два указателя идут в **одну сторону** с разной скоростью: `slow` на шаг,
`fast` на два. Из этого следуют три факта, на которых стоит весь паттерн:

1. Когда `fast` дойдёт до конца, `slow` будет ровно **в середине**.
2. Если в списке есть **цикл**, `fast` неизбежно догонит `slow` (расстояние
   между ними сокращается на 1 за шаг — проскочить нельзя).
3. Разведя указатели на `k` шагов, получаем «k-й с конца» за один проход.

Всё это — `O(n)` время, `O(1)` память, без предварительного знания длины.

## Триггеры

- связный список + «середина», «цикл», «k-й с конца», «палиндром»;
- «без дополнительной памяти» для списка;
- задача про повторяющиеся состояния (Happy Number — тот же цикл, но на числах);
- «найти дубликат в массиве 1..n за O(1) памяти» (Floyd на массиве-как-функции).

## Скелеты кода

**Узел** (пиши на автомате):

```python
class ListNode:
    def __init__(self, val: int = 0, next: "ListNode | None" = None) -> None:
        self.val = val
        self.next = next
```

**Середина**

```python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
return slow          # при чётной длине — ВТОРАЯ из двух середин
```

Первую середину даёт `while fast.next and fast.next.next`. Какая нужна —
уточняющий вопрос к интервьюеру.

**Есть ли цикл**

```python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:
        return True
return False
```

Сравнение через `is` — сравниваем объекты, не значения.

**Начало цикла (алгоритм Флойда)**

```python
slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next
    if slow is fast:
        slow = head                 # один возвращается в начало
        while slow is not fast:     # дальше оба по шагу
            slow, fast = slow.next, fast.next
        return slow                 # точка входа в цикл
return None
```

Почему работает: если до цикла `a` шагов, а встреча произошла в `b` шагах внутри
цикла длины `c`, то `2(a + b) = a + b + kc` ⟹ `a = kc − b`. То есть от головы
до входа ровно столько же шагов, сколько от точки встречи до входа. На собесе
достаточно знать вывод и уметь показать его на схеме.

**Разворот списка** — половина задач требует его как подшаг:

```python
def reverse(head: ListNode | None) -> ListNode | None:
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt
    return prev
```

**Dummy-узел** — против edge-кейса «удаляем/вставляем в голову»:

```python
dummy = ListNode(0, head)
...работаем...
return dummy.next
```

## Разобранный эталон: Palindrome Linked List за O(1) памяти

> Проверить, что связный список — палиндром. Требование: `O(n)` время, `O(1)` память.

**Наивно.** Скопировать значения в список и сравнить с разворотом: `O(n)` памяти.
Это нормальный первый ответ, его надо озвучить, а потом улучшить.

**Идея.** Найти середину быстрым/медленным указателем → развернуть вторую
половину → идти навстречу с двух концов, сравнивая значения.

```python
def is_palindrome(head: ListNode | None) -> bool:
    """Проверка, что список — палиндром.

    Середина через fast/slow, разворот второй половины, сравнение.
    Время O(n), память O(1).
    """
    if not head or not head.next:
        return True

    slow, fast = head, head
    while fast.next and fast.next.next:      # slow — ПЕРВАЯ середина
        slow = slow.next
        fast = fast.next.next

    second = reverse(slow.next)              # развернули хвост
    first = head
    ok = True
    node = second
    while node:
        if first.val != node.val:
            ok = False
            break
        first = first.next
        node = node.next

    slow.next = reverse(second)              # хороший тон: восстановить список
    return ok
```

Строка восстановления — необязательна для тестов, но интервьюер почти всегда
спрашивает: «ты испортил входные данные, это нормально?» Ответ «я восстановил»
или «я уточнил, что вход портить можно» — сильный.

## Тот же паттерн вне списков

**Happy Number:** последовательность сумм квадратов цифр либо приходит к 1,
либо зацикливается. `slow = step(slow)`, `fast = step(step(fast))`.

**Find the Duplicate Number:** массив длины `n+1` со значениями `1..n` —
это функция `i → nums[i]`, то есть «связный список» с циклом. Флойд находит
дубликат за `O(n)` время и `O(1)` память, не портя массив.
Красивая задача, любят на секциях.

## Типичные ошибки

1. **`fast.next.next` без проверки `fast.next`** → `AttributeError` на чётной длине.
2. **`==` вместо `is`** при сравнении узлов.
3. **Потеря `next` при развороте** — забыли `nxt = cur.next` до перезаписи.
4. **Не обработан пустой список / список из одного узла.**
5. **Возвращают `cur` вместо `prev`** из разворота (`cur` уже `None`).
6. **Не спросили про чётную длину** — какая середина нужна.

но попросят объяснить, что внутри).
