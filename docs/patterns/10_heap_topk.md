# Паттерн 10 — Heap / Top-K

> **Приоритет: технические секции**, но задача «k самых частых» стабильно
> появляется и на отборах.

## Идея простыми словами

Куча (`heapq`) даёт доступ к минимуму за `O(1)` и вставку/удаление за `O(log n)`.
Она нужна там, где **минимум/максимум меняется по ходу дела** и пересортировывать
каждый раз слишком дорого.

Главный приём паттерна: **«k самых больших» — держим мин-кучу размера k**.
Как только размер превысил `k`, выкидываем минимум. В куче всегда остаются
`k` лучших, а вершина — это ровно k-й по величине.

Сравнение подходов для «найти k самых больших из n»:

| Способ | Время | Память |
|---|---|---|
| `sorted(nums)[-k:]` | `O(n log n)` | `O(n)` |
| куча размера k | `O(n log k)` | `O(k)` |
| Quickselect | `O(n)` в среднем | `O(1)` |

При `k` много меньше `n` куча заметно лучше. И это правильный ответ
на вопрос «а если данных 10⁹ и они не влезают в память?» — потоковая обработка
кучей требует только `O(k)`.

## Триггеры

- «k самых больших / частых / близких»;
- «медиана потока», «k-й элемент»;
- «объединить k отсортированных списков»;
- «минимальное число ресурсов» (переговорки, процессоры) — куча освобождений;
- задача про приоритеты и расписание;
- Дейкстра ([паттерн 09](09_graphs.md)) — тоже куча.

## Базовые операции

```python
import heapq

h: list[int] = []
heapq.heappush(h, x)         # O(log n)
smallest = h[0]              # O(1), не снимая
heapq.heappop(h)             # O(log n)
heapq.heapify(nums)          # O(n), на месте
heapq.nlargest(k, nums)      # готовое решение, O(n log k)
heapq.nsmallest(k, nums, key=...)
```

**Макс-куча** — через отрицание: `heappush(h, -x)`, снимаем `-heappop(h)`.
Другого способа в Python нет, и на собесе это надо просто назвать.

**Кортежи** сортируются по первому элементу:

```python
heapq.heappush(h, (freq, word))
heapq.heappush(h, (dist, node))
```

Если первые равны, Python сравнит вторые — а если они несравнимы, будет `TypeError`.
Страховка: `(priority, счётчик, объект)`.

## Скелет: Top-K за O(n log k)

```python
import heapq
from collections import Counter

def top_k_frequent(nums: list[int], k: int) -> list[int]:
    """k самых частых элементов.

    Мин-куча размера k. Время O(n log k), память O(n).

    >>> sorted(top_k_frequent([1, 1, 1, 2, 2, 3], 2))
    [1, 2]
    >>> top_k_frequent([1], 1)
    [1]
    """
    freq = Counter(nums)
    heap: list[tuple[int, int]] = []
    for value, count in freq.items():
        heapq.heappush(heap, (count, value))
        if len(heap) > k:
            heapq.heappop(heap)          # выкинули наименее частый
    return [value for _, value in heap]
```

Стоит знать и решение за `O(n)` — **bucket sort по частотам**: массив списков,
индекс = частота, идём с конца. Назвать оба варианта — сильный ход.

## Разобранный эталон: Kth Largest Element in an Array

> Найти k-й по величине элемент неотсортированного массива.

**Решение 1 (сортировка).** `sorted(nums)[-k]`, `O(n log n)`. Назвать как базу.

**Решение 2 (куча).** Мин-куча размера `k`, ответ — `heap[0]`. `O(n log k)`.

```python
def find_kth_largest(nums: list[int], k: int) -> int:
    """k-й по величине элемент.

    Время O(n log k), память O(k).

    >>> find_kth_largest([3, 2, 1, 5, 6, 4], 2)
    5
    >>> find_kth_largest([3, 2, 3, 1, 2, 4, 5, 5, 6], 4)
    4
    """
    heap: list[int] = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]
```

**Решение 3 (Quickselect).** Как быстрая сортировка, но рекурсия идёт только
в нужную половину → `O(n)` в среднем, `O(n²)` в худшем (лечится случайным опорным).
Уметь **рассказать** словами — писать на секции обычно не просят.

Разбор трёх решений с разменом «время / память / худший случай» —
именно та беседа, ради которой эту задачу и дают.

## Приём: две кучи (медиана потока)

Числа приходят по одному, после каждого нужна медиана.
Держим две кучи: макс-куча `low` (меньшая половина, через отрицание)
и мин-куча `high` (большая половина). Инвариант: размеры различаются не больше чем на 1.

```python
class MedianFinder:
    def __init__(self) -> None:
        self.low: list[int] = []    # макс-куча (хранит -x)
        self.high: list[int] = []   # мин-куча

    def add(self, num: int) -> None:
        heapq.heappush(self.low, -num)
        heapq.heappush(self.high, -heapq.heappop(self.low))   # балансировка
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def median(self) -> float:
        if len(self.low) > len(self.high):
            return float(-self.low[0])
        return (-self.low[0] + self.high[0]) / 2
```

`add` — `O(log n)`, `median` — `O(1)`. Задача «Find Median from Data Stream»
любима на секциях уровня middle-стажёр.

## Типичные ошибки

1. **Ждут макс-кучу от `heapq`** — её нет, только через отрицание.
2. **Держат кучу размера n**, когда достаточно `k` → `O(n log n)` вместо `O(n log k)`.
3. **`TypeError` при равных приоритетах** — несравнимые вторые элементы кортежа.
4. **Меняют элемент внутри кучи** — структура ломается; правильно класть новую
   запись и пропускать устаревшие (как в Дейкстре).
5. **Забывают `heapify` за `O(n)`** и вставляют элементы по одному за `O(n log n)`.
6. **Не спрашивают, что делать при `k > len(nums)`.**
