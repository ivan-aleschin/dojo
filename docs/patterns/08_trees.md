# Паттерн 08 — Деревья: BFS / DFS

> **Приоритет: технические секции.** Деревья — самый частый структурный вопрос
> живого собеса: их легко нарисовать на доске и легко усложнять вопросами.

## Идея простыми словами

Дерево — это рекурсивная структура: у узла есть значение и поддеревья, которые
устроены точно так же. Отсюда шаблон почти любого решения:

> **Реши задачу для поддеревьев → собери из их ответов ответ для узла.**

Два способа обхода:
- **DFS (в глубину)** — рекурсия, идём до листа и возвращаемся. Память `O(h)` — высота.
- **BFS (в ширину)** — очередь `deque`, идём по уровням. Память `O(ширины)`.

Выбор зависит от вопроса: «уровни / кратчайший путь» → BFS,
«всё поддерево / путь сверху вниз» → DFS.

## Триггеры

- «уровень», «по слоям», «правый вид дерева», «минимальная глубина» → **BFS**;
- «глубина», «сумма пути», «проверить свойство поддерева» → **DFS**;
- «BST» (бинарное дерево поиска) → почти всегда inorder или спуск по сравнению;
- «наименьший общий предок» → DFS с возвратом.

## Три порядка обхода DFS

```python
def preorder(node):     # корень → левое → правое.  Копирование, сериализация
    if not node: return
    visit(node); preorder(node.left); preorder(node.right)

def inorder(node):      # левое → корень → правое.  Для BST даёт СОРТИРОВАННЫЙ порядок
    if not node: return
    inorder(node.left); visit(node); inorder(node.right)

def postorder(node):    # левое → правое → корень.  Когда ответ узла зависит от детей
    if not node: return
    postorder(node.left); postorder(node.right); visit(node)
```

**Факт, который надо знать:** inorder-обход BST выдаёт значения по возрастанию.
Отсюда решаются «k-й наименьший в BST» и «проверь, что это BST».

## Скелет DFS «снизу вверх»

```python
def max_depth(root: TreeNode | None) -> int:
    """Максимальная глубина дерева.

    Время O(n), память O(h) на стеке рекурсии.
    """
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

Три строки, но в них весь паттерн: база (пустой узел), рекурсия для детей,
сборка ответа. Все задачи на деревья пишутся по этому шаблону.

## Скелет BFS по уровням

```python
from collections import deque

def level_order(root: TreeNode | None) -> list[list[int]]:
    """Обход по уровням.

    Время O(n), память O(ширины уровня).
    """
    if not root:
        return []
    out: list[list[int]] = []
    q = deque([root])
    while q:
        level = []
        for _ in range(len(q)):      # ФИКСИРУЕМ размер уровня ДО цикла
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        out.append(level)
    return out
```

`for _ in range(len(q))` — сердце уровневого BFS. Без него уровни смешаются.
Из этого скелета получаются: правый вид дерева (`level[-1]`), средние по уровням,
зигзаг (`level[::-1]` через раз), минимальная глубина (первый лист).

## Разобранный эталон: Validate Binary Search Tree

> Проверить, что дерево — корректный BST: все значения слева от узла строго меньше,
> справа — строго больше.

**Ловушка.** Наивная проверка «левый ребёнок < узла < правый ребёнок» **неверна**:

```
      5
     / \
    1   7
       / \
      3   8      ← 3 < 5, но лежит в правом поддереве. Не BST.
```

Свойство глобальное: узел должен укладываться в **диапазон**, который сужается
при спуске. Это классический вопрос-подвох, его задают, чтобы посмотреть,
проверяет ли кандидат гипотезу на контрпримере.

```python
def is_valid_bst(root: TreeNode | None) -> bool:
    """Проверка BST через сужающийся диапазон.

    Время O(n), память O(h).
    """
    def check(node: TreeNode | None, low: float, high: float) -> bool:
        if not node:
            return True
        if not (low < node.val < high):
            return False
        return (check(node.left, low, node.val)
                and check(node.right, node.val, high))

    return check(root, float("-inf"), float("inf"))
```

**Альтернатива:** inorder-обход и проверка строгого возрастания. Хорошо назвать
оба решения — интервьюеру нравится, когда кандидат видит связь между задачами.

## Приём: ответ узла и «ответ через узел» — это разные вещи

Diameter, Max Path Sum, Longest Univalue Path устроены одинаково: рекурсия
возвращает одно (что можно **продолжить вверх**), а глобальный максимум
обновляется другим (что **замыкается** в этом узле).

```python
def diameter_of_binary_tree(root: TreeNode | None) -> int:
    best = 0

    def depth(node: TreeNode | None) -> int:
        nonlocal best
        if not node:
            return 0
        left, right = depth(node.left), depth(node.right)
        best = max(best, left + right)     # путь ЧЕРЕЗ узел — замыкается тут
        return 1 + max(left, right)        # наверх отдаём только одну ветку

    depth(root)
    return best
```

Понимание этой разницы — то, что отличает «зубрил» от «понял». Проговаривай вслух:
«наверх я могу продолжить только одну ветку, поэтому возвращаю max, а в ответ
записываю сумму обеих».

## Типичные ошибки

1. **Нет базы рекурсии** `if not node: return` → падение на `None`.
2. **Локальная проверка BST** вместо диапазона.
3. **BFS без фиксации размера уровня.**
4. **`list.pop(0)` вместо `deque.popleft()`** → `O(n²)`.
5. **Забывают про глубину рекурсии** на «дереве-цепочке» из 10⁵ узлов.
6. **Путают «путь через узел» и «путь вниз»** в задачах на максимальный путь.
7. **Не спрашивают, могут ли значения повторяться** — для BST это меняет строгость сравнений.
